# WebView 浏览专项检查

日期：2026-09-16。工作区版本：Soulo 1.1.7（24）。

## 已复现并修复的问题

开启 GPC 且请求命中启用站点时，导航代理会取消原请求，并调用 `WKWebView.load` 加上隐私请求头。原代码未限制目标 frame，因此 iframe 的请求也会触发主页面导航，导致内嵌内容替换整页。

本地 HTTP 网页复现：打开 `/iframe`，其中内嵌 `/child`；修复前顶部地址变成 `/child`，原页面消失。新增测试在修复前失败，修复后通过。

修改位于 `WebViewRepresentable.Coordinator`：只有明确指向主 frame 的 GET 导航才通过重新加载改写隐私请求头；iframe 和没有 target frame 的新窗口交由 WebKit 处理。主页面的 GPC 请求头仍保留，POST 不重新提交。

这是检查中发现的既有风险，不是本次正方形缩略图或版本号修改引入的问题。

## 新增的实际导航回归

`SouloTests/WebBrowsingRegressionTests.swift` 使用临时本地 HTTP 服务和产品实际的 `WebViewRepresentable`，不依赖外网。

1. GPC 开启时 iframe 正常嵌入，顶部 URL 不变，主请求带 `Sec-GPC: 1`。
2. POST 表单数据完整且只提交一次；303 跳转、前进后退和新窗口链接正常。
3. 新窗口 POST 提交保留包含 `+`、空格和 `&` 的表单数据。
4. 广告标记动态更新后，其他 document-start 脚本仍能在刷新后执行；SPA 路由变更正确更新页面级广告规则。
5. 快速连续导航、下拉刷新停止动画、网络失败显示错误，以及再次打开网页后的恢复。

以上五项均已单独通过。原有 WebView、导航、标签、脚本与隐私等相关测试先行运行了 191 项，全部通过。

## 测试就绪条件修正

第一次全量测试与 Release 编译同时运行，400 项中有三项用例、五处失败；日志记录 WebContent/GPU 进程启动耗时约 23 秒。之后单独复跑又出现阅读器滚动位置及广告测试页面尚未就绪的问题，因此没有仅凭并行编译就认定为环境原因，也没有将这些运行计为通过。

复查测试源码发现：

- 广告标记测试在页面未就绪时仍会返回 WebView，后续断言继续操作缺失的 DOM；现改为等待该文档的 `didFinish`，导航失败或超时直接结束准备阶段。
- 截图/翻译测试仅检查 `document.readyState`，可能读到初始空白文档；现改为等待实际导航完成。
- 阅读器外观测试在 `scrollTo` 返回后立即改字号，未确认原生滚动位置已经建立；现等待实际滚动位置及外观更新，再验证保留位置。原有字号、行间距、文档未重载和滚动位置断言均保留。

修改仅影响测试就绪与失败处理，不修改广告过滤、翻译或阅读器功能代码。三个相关测试组分组重跑共 91 项，全部通过。

剩余 309 项中，308 项通过，一项阅读器测试在原生页面尺寸尚未更新时读取到临时进度 1。该测试的初始布局、章节跳转检查也由固定延迟改为等待实际布局与进度更新，保留“初始进度小于 0.05”、跳转位置和字体断言。随后阅读器整组 8 项通过。

## 继续补查：登录弹窗、标签恢复及广告规则编译

代码检查发现广告规则异步完成时没有重新读取过滤总开关和当前页面的兼容策略：用户关闭过滤，或已进入登录/验证页后，旧任务仍可能重新装入网络过滤规则。规则预热还存在旧编译结果覆盖新缓存、切换签名时旧规则暂时被误认为新规则的问题。

本轮修复：

- 缓存和编译结果统一经过当前状态检查后再安装；关闭过滤、站点白名单及验证页面豁免均生效。
- 新签名开始编译时清空旧缓存，预热完成时核对签名，避免过期结果覆盖新配置。
- 异步任务弱引用 WebView 和模型；关闭或挂起的标签不重新安装规则，同一个 WebView 恢复后可以接收仍然有效的规则。

新增三项回归：

1. 模拟登录弹窗通过 `window.open` 打开，共享父页 Cookie，写入登录 Cookie，使用 `window.opener.postMessage` 返回结果并 `window.close`；父页面地址保持不变。
2. 使用产品实际 `WebViewRepresentable` 连续拆卸/恢复三次，确认 WebView 身份、未提交表单、JavaScript 状态和前后退历史保留，注入脚本数量不增长，页面没有重复请求。
3. 使用实际 WKContentRuleList 和本地资源请求，先确认广告路径被拦截，再模拟编译完成时已关闭开关、已进入登录页面两个状态，确认资源恢复加载。该测试控制结果交付顺序，不依赖偶发的真实编译时序来触发竞态。

本轮新增及原有浏览导航共 8 项先行通过。随后广告过滤、订阅、手动标记、隐私、外部导航、选中文字搜索、标签与 WebView 模型等相关回归共 150 项全部通过：`/tmp/soulo-webview-followup-final-117.xcresult`。随后进一步明确同一个 WebView 恢复时可以接收有效编译结果，并重新构建、重跑 8 项实际浏览回归，全部通过：`/tmp/soulo-webview-followup-lifecycle-117.xcresult`。这次结果不代表重新执行了全量 403 项用例。
