# Soulo 产品路线图与任务拆解

更新：2026-09-05 · 代码基线：`95dbee1` · 状态：0–5 现有功能完善，其余阶段待实施

目标：做一个安静、快速、好看的浏览器。无推送、无新闻流、无产品广告；浏览、播放、下载、阅读都能顺手完成。功能增加时，首页和日常操作仍然保持简洁。

本文基于当前源码审查。已有实现不等于已经完成所有兼容性验收；性能指标是拟定目标，不是现有实测成绩。

用户确认：0–5 已有对应功能，当前工作是逐项检查、完善与回归，不重复建设模块。下文这些阶段的清单作为复核范围，不表示每项尚未实现。发现明确问题再做小范围修改，复用现有流程，保留既有兼容路径。本轮记录见 [现有功能完善记录](EXISTING_FEATURES_REVIEW.md)。

## 2. UI / UX 共同标准

### 信息架构与视觉

- 首页以搜索框、用户收藏和壁纸为主。没有新闻流、广告位、自动播放或轮播宣传。
- 浏览器底部保留高频导航；翻译、阅读、下载、扩展按当前网页上下文出现，更多能力收进工具面板。
- 工具面板分为“当前网页”“媒体与文件”“浏览器设置”。不把每项新能力都做成首页常驻按钮。
- 资料库统一承接下载、文件和书籍，用分区保留不同任务习惯；书库引用文件，不重复复制大文件。
- 播放时才显示迷你播放器；完整播放页和阅读页采用沉浸布局，轻触唤出工具，返回保留位置。
- 使用系统字体、统一字级、8pt 间距基准、克制的单一强调色和一致图标。壁纸上的文字必须有稳定对比度，长文本页面不叠加复杂背景。
- 同时设计浅色、深色、最窄支持屏幕、横屏及 iPad 分栏；保留并校验已有窗口间的状态隔离。

### 可验收的交互要求

| 项目 | 验收方式 |
| --- | --- |
| 易发现 | 下载、翻译、进入阅读、调整倍速，从相关页面最多两次点击进入；菜单标签使用具体动作 |
| 即时反馈 | 点击在 100ms 内出现可见反馈；耗时操作显示真实阶段/进度，允许取消，失败给出恢复入口 |
| 状态完整 | 每个模块评审空、加载、成功、失败、离线；适用时补齐暂停、重试、取消和恢复状态 |
| 连贯 | 返回保留滚动位置、筛选与选中项；更换播放器形态保留进度；修改字体保留阅读锚点 |
| 可恢复 | 可撤销删除或提供明确确认；批量失败显示具体条目；不得用假成功提示吞掉错误 |
| 无障碍 | 交互目标至少 44×44pt；正文对比度目标 4.5:1；支持 Dynamic Type、VoiceOver、减少动态效果 |
| 国际化 | 保留现有 50 种 UI 语言；长文案不截断关键操作，阿拉伯语等 RTL 布局单独验收 |
| 克制 | 权限仅在用户触发相应能力时申请；不用连续弹窗、强制引导或评分弹窗打断任务 |

“世界级”作为质量目标，以完整任务体验验收。每阶段先完成关键页面与状态设计，再实现；交付时提供真机录屏和问题清单。用至少 5 位首次使用者测试搜索、下载、翻译、播放、阅读任务，目标至少 4 人无需提示即可完成各任务，并记录误触和困惑点。小样本用于发现问题，不宣称统计结论。

### 性能预算

先用 Release 真机建立基线，建议基准机 iPhone 12，并覆盖最低支持系统、最新正式系统和一台近期设备。若基准不可用，记录替代设备，避免混合比较。

- 启动目标：进程启动至首页可操作，冷启动 P50 ≤500ms、P95 ≤800ms；暖启动 P95 ≤200ms。首帧和可交互时间分别记录，不能以显示启动图代替启动完成。
- 每个基准场景至少测 30 次，记录设备、系统、温度、安装状态、数据规模；首次安装和系统缓存影响单列。
- 首次打开网页另测本地固定页面与真实网络页面。不能把慢工作全部延后，换来第一次搜索卡顿。
- 无网络时仍可进入首页、管理本地文件、打开已支持的本地书籍。
- 滚动和手势在目标设备刷新率下检查掉帧；新增模块不在首页同步初始化大索引、规则库或解析器。
- 每个里程碑复测启动、内存和包体；相对上一版超过 10% 的退化必须定位，并有明确处理结论。

## 3. 从简单到难的实施顺序

难度按当前基础、新增工作量和兼容性风险估计。同档任务会因依赖调整顺序；不把“加一个倍速按钮”和“所有站点稳定 16 倍速”视为同一项任务。

| 顺序 | 阶段 | 难度 | 可独立交付的成果 | 依赖 |
| --- | --- | --- | --- | --- |
| 0 | 体验规范与性能基线 | 小 | 首页/工具面板/资料库原型、公共组件、启动测量 | 无 |
| 1 | 三无与自定义完善 | 小—中 | 安静首页、无通知策略、壁纸/图标/主页/引擎/UA | 0 |
| 2 | JS 扩展打磨 | 中 | 自建、编辑、运行、按站点启停及错误恢复 | 1 |
| 3 | 翻译完善 | 中 | 整页 + 划词，首批 14 种语言的实测支持表 | 0 |
| 4 | 广告过滤完善 | 中—大 | 多语言/第三方订阅、手动标记、规则编辑、例外 | 0，兼容性预研 |
| 5 | 下载与基础文件管理 | 中—大 | 手动下载、目录、导入、移动复制、文本编辑与编码 | 0 |
| 6 | 基础媒体播放器 | 中—大 | 链接分享、0.5–2 倍、单曲循环、应用内浮窗 | 5 的文件模型 |
| 7 | 基础阅读与电子书 | 大 | 网页正文阅读、TXT/PDF 阅读、书库与位置恢复 | 5 |
| 8 | 压缩与高级文件管理 | 大 | ZIP → 加密 ZIP → 7z/RAR 解压及 7z 创建 | 5，格式预研 |
| 9 | EPUB 与智能拼页 | 大 | EPUB 阅读、章节导航、小说连续阅读 | 7 |
| 10 | Wi-Fi 文件传输 | 大 | 局域网配对、上传下载、进度、冲突和断线处理 | 5 |
| 11 | 高级媒体能力 | 很大 | 后台、锁屏、AirPlay、系统 PiP，扩展到 8/16 倍 | 6，媒体预研 |
| 12 | Kindle 及旧格式适配 | 很大/不确定 | 按格式验收 MOBI/AZW/AZW3/AZW4/PRC/PDB | 9，格式预研 |

阶段 0 同期执行小范围技术验证：媒体高倍速与 PiP、广告引擎选型、加密压缩、旧电子书格式。每项先限定 2–3 个工作日收集证据，产出支持矩阵、包体/内存影响与方案结论；这只是验证时间，不是功能工期。未完成验证的能力保留在需求中，不提前写成官网已支持。

## 4. 可执行任务清单

以下复选框全部表示待完成任务。每项交付应包含实现、适用系统/内容边界、验收证据和已知问题。

### P0：规范、测量与预研

- [ ] P0-01：整理现有页面与入口，标记重复设置、过长路径、状态不一致问题，按影响排序。
- [ ] P0-02：设计首页、网页工具面板、资料库、播放页、阅读页及其错误/空状态，确定排版与组件规范。
- [ ] P0-03：增加启动分段测量，区分首帧、可交互、首次网页加载；建立固定数据与真机基线。
- [ ] P0-04：验证普通 MP4/音频、HLS、网页 video 的倍速、后台和 PiP，记录每类媒体的实际结果。
- [ ] P0-05：验证 ABP 规则支持、压缩库与阅读库，记录许可证、iOS 集成方式、格式差异和资源开销。

### P1：三无、自定义与启动改进

- [ ] P1-01：审计所有通知入口。按“无推送”的严格默认方案，应用和扩展均不发系统通知、不请求通知权限；扩展通知 API 返回明确不支持，提供应用内运行结果。锁屏播放控制另属用户主动播放状态。
- [ ] P1-02：审计首页、搜索空态和设置，去除产品广告及主动新闻/热榜推荐；保留用户输入后触发的搜索建议与用户自己添加的网站。
- [ ] P1-03：根据测量结果优化数据库、壁纸解码、标签恢复、规则编译和 WebView 预热；确保首次导航也流畅。已有延时任务仍需验证实际收益。
- [ ] P1-04：壁纸选择提供实时预览、裁剪、可读性调整和恢复默认；失败时使用本地稳定背景。
- [ ] P1-05：站点名称/图标、默认主页、搜索引擎编辑统一表单；校验 URL 和搜索占位符，提供试用预览。
- [ ] P1-06：提供全局和单站点 UA；明确继承关系，切换后仅在用户确认刷新时重载；一键恢复默认。

验收：首次打开无通知请求和内容推荐打扰；无网可用；设置跨重启保留；启动达到预算或留下逐项量化差距，不能提前宣传已达标。

### P2：JavaScript 扩展

- [ ] P2-01：打通新建 → 编辑 → 保存 → 当前网页运行，显示运行结果和错误行号。
- [ ] P2-02：完善语法高亮、查找、撤销、草稿恢复和示例脚本；避免在手机上堆桌面 IDE 面板。
- [ ] P2-03：明确脚本作用站点、运行时机和所需能力；按站点暂停，私密模式默认不运行外部脚本。
- [ ] P2-04：覆盖导入、导出、更新失败、回退和全部暂停；扩展通知遵守 P1 策略。

验收：用户能在当前网页运行自建脚本；不匹配站点不执行；脚本错误不阻断浏览；页面被异常脚本拖慢后可从原生入口禁用并恢复。完整 Chrome/Firefox API 兼容不属于“运行自己的 JS”这一阶段。

### P3：网页翻译

- [ ] P3-01：确认 Apple 真机与 Google 路径、iOS 17 降级体验、语言包准备及不可用提示。
- [ ] P3-02：统一整页翻译入口，支持取消、查看原文、恢复原文与目标语言记忆。
- [ ] P3-03：选中文字后就地翻译，保留选择位置，提供复制、朗读（如当前语言可用）与关闭。
- [ ] P3-04：针对动态加载、iframe、混合语言、长文章处理分批翻译与失效恢复；不改写密码框和用户输入。
- [ ] P3-05：建立首批 14 种语言清单及源/目标语言对矩阵；建议候选为简中、繁中、英、日、韩、法、德、西、葡、意、俄、阿、印尼、土耳其语，以引擎真机验证为准，未通过的单列处理。

验收：文字选择和整页路径均可恢复原文；长页面不冻结；每种已宣传语言有真实样本；联网服务与本地语言包路径清楚，不能把“14 种语言”误写成“所有系统均支持 14 种离线翻译”。Apple 提供运行时语言可用性查询。[Apple 文档](https://developer.apple.com/documentation/translation/languageavailability)

### P4：广告过滤与手动标记

- [ ] P4-01：确定使用现有 ABP 语法适配器还是接入其他引擎。若采用 Adblock Plus 名称/代码，先完成相应集成和授权核对；兼容订阅语法不能直接视为内置官方引擎。[ABP 项目说明](https://adblockplus.org/en/about)
- [ ] P4-02：多语言推荐规则按需启用，支持第三方订阅 URL、更新时间、来源与错误；更新失败保留上一份有效规则。
- [ ] P4-03：审计当前解析器默认 2,500 条网络规则/1,200 条元素规则限制及不支持的高级语法；展示导入、启用、跳过数量和原因，避免静默截断。
- [ ] P4-04：实现点选元素 → 高亮预览 → 调整范围 → 保存站点规则；支持撤销、编辑、删除，不能误吞网页点击造成无法退出。
- [ ] P4-05：覆盖侵入式弹层、广告 iframe、动态注入和页面占位；提供站点暂停与误拦截恢复入口。

验收：固定广告样本可复现；登录、支付、验证码等关键网页流程做回归；订阅损坏或离线不清空有效保护。拦截数量必须有真实统计来源，不伪造指标。

### P5：下载与文件管理基础

- [ ] P5-01：完善粘贴链接手动下载、文件名/目录选择、暂停继续、重试、完成后打开；明确受鉴权链接与可恢复下载的条件。
- [ ] P5-02：建立统一文件标识和目录模型；下载记录、阅读位置、播放记录引用该模型，重命名或移动不丢关联。
- [ ] P5-03：新建目录/文本、重命名、排序搜索、多选、移动复制、删除恢复、导出分享；重名时明确保留两份/替换/取消。
- [ ] P5-04：从系统“文件”和照片选择器导入图片/视频；覆盖大文件、授权拒绝、空间不足、重复导入。
- [ ] P5-05：纯文本预览及编辑，支持 UTF-8/UTF-16/GB18030/Big5 等经样本验证的编码；切换解码先预览，保存前防止不可表示字符被静默替换。
- [ ] P5-06：用临时文件加原子提交避免半成品覆盖原件；跨重启恢复任务，正确显示部分失败。

验收：中文名、特殊字符、大文件、多个并发任务和低磁盘空间均有样本；下载 → 移动 → 打开 → 分享完整可用；不能因任务失败留下“已完成”的损坏文件。

### P6：基础媒体体验

- [ ] P6-01：建立统一播放会话，连接网页资源和本地文件；切换媒体时防止多个播放器同时发声。
- [ ] P6-02：实现播放暂停、进度、快进后退、0.5–2 倍、单曲循环、分享原网页/可用媒体链接。
- [ ] P6-03：实现应用内音频/视频悬浮与展开，支持拖动吸边，避让键盘、安全区和浏览器工具栏。
- [ ] P6-04：保存进度与倍速偏好；播放失败区分过期链接、网络问题和不支持的媒体。

验收：预览、完整播放器和应用内浮窗保持同一播放进度；单曲循环在曲末生效；链接需要登录时如实提示。应用内浮窗和跨应用系统画中画分别验收。

### P7：基础阅读与书库

- [ ] P7-01：提取文章正文、标题和图片，提供字体/字号/行距/主题；提取失败可返回原网页且不丢位置。
- [ ] P7-02：建立书库导入、封面、最近阅读、书签和稳定阅读位置；复用文件模型。
- [ ] P7-03：TXT 按块加载、编码选择、章节识别、全文搜索；大文本不整本加载到主线程。
- [ ] P7-04：PDF 阅读、缩放、页码、目录、搜索和书签；扫描 PDF 无文本时明确搜索能力，OCR 另立需求。

验收：后台返回、退出重开、调字体或移动书籍后均能恢复阅读位置；正文排版覆盖中文标点、英文长词与 RTL 样本。

### P8：压缩、解压与加密

- [ ] P8-01：先完成 ZIP 创建/解压、预览目录、目标目录选择、进度与取消。
- [ ] P8-02：添加加密 ZIP 创建/解压，验证密码错误、中文密码与其他常用软件互操作。
- [ ] P8-03：添加 7z 创建/解压及加密能力；普通格式支持与加密支持分开验证，不能由库支持“7z”推断全部可用。
- [ ] P8-04：添加 RAR/RAR5 解压及经验证的加密样本；分卷、特殊算法列入独立兼容矩阵。
- [ ] P8-05：阻止越界路径写入，限制解压总量/条目数量/资源消耗；损坏包和取消操作不破坏已有文件。

验收：每个支持组合至少覆盖正常、错误密码、损坏、同名、取消、空间不足样本。用户要求的 RAR 创建/加密创建保留为选型决策项：候选 libarchive 只提供 RAR 读取，不能用它兑现 RAR 压缩；未找到适用实现前不承诺交付日期。[libarchive 格式表](https://github.com/libarchive/libarchive/wiki/LibarchiveFormats)

### P9：EPUB 与小说连续阅读

- [ ] P9-01：接入并评估 EPUB 阅读引擎，完成目录、章节跳转、样式、图片、进度、书签和搜索；固定版式单独验收。
- [ ] P9-02：正文阅读识别下一页/下一章链接，按需预取，显示当前章节与来源。
- [ ] P9-03：内容去重、章节顺序校验、重复链接终止；站点适配规则可停用。
- [ ] P9-04：处理加载失败、登录/付费章节与结构变化；保留手动下一章和返回原网页，停止无效循环请求。

验收：在已声明适配的小说/文章站点样本上无重复章、漏章或无限请求；取消后停止预取；未适配网站清楚降级。Readium 是 EPUB/PDF 的候选基础，不代表覆盖 Kindle 系列。[Readium 文档](https://readium.org/swift-toolkit/)

### P10：Wi-Fi 传输

- [ ] P10-01：由用户显式开启本地传输，申请本地网络访问，显示当前地址和一次性配对码/二维码。
- [ ] P10-02：电脑端简洁网页支持拖入上传、下载、多选、进度和同名处理，复用文件管理规则。
- [ ] P10-03：仅暴露用户选择的目录；配对过期、主动关闭和网络切换后失效，传输结束清晰反馈。
- [ ] P10-04：覆盖断线、重新连接、大文件和后台切换；未支持断点续传时明确重新开始，不能假装继续。

验收：同局域网两台真实设备互传并校验完整性；未配对不可读取文件；停用后连接关闭；说明需要保持传输页面活跃的系统条件。

### P11：后台、AirPlay、画中画与高倍速

- [ ] P11-01：配置音频会话及后台能力，接入锁屏信息与远程播放控制，处理电话/闹钟打断和耳机断开。
- [ ] P11-02：接入系统 PiP 的进入/退出/恢复，验证后台、返回应用、多窗口及屏幕旋转。
- [ ] P11-03：接入 AirPlay 路由选择，验证设备连接/断开、进度接续和接收端能力差异。
- [ ] P11-04：从已稳定的 0.5–2 倍扩展到 4/8/16 倍，提供常用档位和精细调节；分别测网页播放器与原生播放器。
- [ ] P11-05：建立“来源 × 容器/编码 × 播放方式 × 倍速 × 系统/设备”的矩阵，记录实际播放速率、音画同步、温升和耗电。
- [ ] P11-06：资源不支持接管或所选倍速时给出可用选项；UI 显示实际状态，不能只改变按钮数值。

验收：普通本地音视频先通过，随后覆盖直播/点播 HLS、鉴权链接和网页媒体；各类 DRM/站点限制明确标记。AirPlay 与高倍速组合单测。Apple 说明超过 2 倍可能受媒体能力和解码限制影响，不能保证所有内容 16 倍仍流畅。[AVPlayer 倍速说明](https://developer.apple.com/library/archive/qa/qa1772/_index.html) 系统 PiP 还涉及音频会话、后台配置与恢复流程。[Apple PiP 文档](https://developer.apple.com/documentation/avkit/adopting-picture-in-picture-in-a-standard-player)

## 5. 里程碑与交付规则

| 里程碑 | 包含阶段 | 用户能获得什么 |
| --- | --- | --- |
| A：安静、顺手 | P0–P4 | 简洁首页、完善自定义/脚本/翻译/拦截，启动有真实数据 |
| B：下载与播放 | P5–P6 | 下载之后就能整理、编辑、分享和悬浮播放 |
| C：阅读与文件工具 | P7–P10 | 书库、正文阅读、EPUB、连续阅读、压缩和 Wi-Fi 传输 |
| D：高级兼容 | P11–P12 | 经实测的高倍速和系统播放能力，以及逐项扩充的旧书格式 |

里程碑内部按完成的阶段小批交付，避免等所有功能完成才发布。困难兼容项的延期不阻塞已验收能力。暂不指定市场版本号和总工期；P0 完成后按真实缺口估算人日，设计、开发、真机兼容测试和修复分别记录。

每次交付完成以下事项：

1. 核对范围与依赖，保留用户现有修改；提供变更、验收结果和未解决问题。
2. 对状态恢复、文件完整性、规则解析等风险编写有意义的自动化测试；视觉调整用实际界面验收，避免只验证实现细节。
3. 运行相关测试与构建；涉及 UI 文案时执行 `python3 scripts/check_localization.py --strict`，持续保留 50 种 UI 语言。
4. 修改工程能力时编辑 `project.yml`，按现有方式运行 `xcodegen generate`。
5. 准备新版本或修改商店发布内容时，按 `AGENTS.md` 同步 50 个语言目录的六项元数据，运行导出和 `--check`，检查版本一致性；记录零宽字符等待人工处理警告。
6. 官网和 App Store 只宣传已经验收的能力；附兼容范围，避免把路线图变成功能承诺。

## 6. 第一轮实施清单

先做 P0 与 P1，完成一个可体验、可测量的产品基础：

1. 现有首页、浏览页、工具面板和设置体验审查，列出按影响排序的问题。
2. 三无入口审计，尤其是当前扩展本地通知路径。
3. 首页、工具面板和自定义设置的可交互原型，包含浅/深色及最窄布局。
4. Release 真机启动与首次导航基线，识别最慢的具体环节。
5. 实施优先级最高的 UI 修复与启动优化。
6. 完善壁纸/站点图标/主页/引擎/UA 的编辑、预览、保存与恢复。
7. 提交四项困难能力的预研报告，标出尚不能承诺的格式或组合。
8. 回归浏览、标签恢复、扩展、翻译和下载；交付真机效果、性能对比及下一阶段估算。

第一轮完成标准：三无策略一致，日常入口清楚，自定义可恢复，启动有前后对比；复杂模块尚未完成的部分在路线图中保持待办。
