# 图片推广过滤与设置说明验收

## 修改原因

用户反馈 `https://ggbgb.na42u.cc/` 的推广轮播和浮动广告在开启广告过滤后仍可见。此前的脚本按钮跳转及完整新标签页修复保留，本次处理页面中的推广元素。

页面将图片解码为 data URL，CSS 类名经过混淆，普通 URL/类名规则无法定位这些图片。新增识别不包含网站域名、品牌名或该页面的随机类名：

- 只读检查图片所属渲染组件中的明确广告统计标记及组件拥有的 DOM 根；限制遍历深度、节点数、图片数和文本量，不执行页面回调，不读取任意应用状态。
- 图片型边缘悬浮推广条还需满足宽高、位置及关闭图标证据；正常固定图片不足以触发隐藏。
- 保留导航、表单、密码输入、媒体播放器等内容。旧广告组件被正常内容复用时移除旧标记。隐藏整个组件后，不为下方正常内容增加点击拦截区域。
- 图片加载后的重新检测合并至现有 100ms 清理任务，没有新增周期轮询。更新派生脚本缓存版本，避免复用旧脚本。

## 验证

`/tmp/soulo-ad-banner-audit-20261106/ImageAdRegression.xcresult`：50 项通过，0 失败、0 跳过，包含真实 iOS WebKit 外站检查。实站 WebKit 识别到两个推广组件及一个悬浮推广条，全部隐藏，7 个正常导航图和页面主体保留。

包含新旧推广识别、晚插入元素、过滤关闭、站点例外、单独关闭图片内置规则、播放器和登录表单、普通图集、固定图片与站内公告样式的反例。统计及摘要：`image-ad-regression.log`、`image-ad-regression-summary.json`。

另以独立 Chrome 会话对比同一实站的完整加载结果（307 张图片）：改前没有匹配到推广；改后隐藏 4 张轮播图、30 张正文推广图所在组件及底部推广条，7 个正常导航图均保留，无页面脚本错误。该次桌面浏览器中新增检测的 20 次测量中位数约 0.8ms，最大约 1.4ms；这不是手机耗时或网页整体加载速度的承诺。证据：`live-comparison.json`。

网站可能调整实现，未知的无标记推广仍依赖订阅规则或用户手动标记；没有通过屏蔽整站图片 CDN 来隐藏广告。

`SettingsAndNavigation.xcresult` 是此前误选整个 UI 测试类后主动中止的宽范围运行，不能作为整组通过的证据；最终结果以上述定向运行和完整 50 项广告/设置检查为准。
