# 功能与效率复查（2026-11-02）

## 检查范围

复查网页导航、视频工具、标签缓存、平台默认搜索、导入、收藏历史、脚本扩展、下载恢复、BT 边播边下、MKV 及 eD2K。保留用户工作区修改。版本保持 1.2.7（51），未安装到用户真机，未提交、暂存或上传。

## 修复一：媒体状态脚本重复扫描

`WebMediaSession.source` 原本在一个 MutationObserver 批次中逐个扫描新增元素，并在每次扫描后清理断开的媒体。新增父节点的扫描实际上已经覆盖其新增子节点。

改为收集仍连接文档的新增元素，仅扫描未被同批祖先覆盖的子树，随后统一清理断开媒体。没有新增定时器，没有修改视频源或网页导航。

`scripts/tests/test_media_session_scanning.cjs` 修改前失败：400 个子节点及两种媒体的同批新增产生 **403 次查询**。修改后为 **1 次**。同一测试还验证所有视频/音频都被发现、仅移除节点的批次仍暂停并释放媒体、已移除新子树不做工作、移动媒体不重复注册事件。

## 修复二：缩放时视频工具尺寸不正确

首次扩大原生检查发现两个已有用例失败：

- 页面缩放至 50% 时，视频按钮测得 96 点，预期 48 点。
- 嵌入播放器使用的父页面比例仍为约 0.397959，预期约 0.596939。

UIScrollView.zoomScale 与 CSS visualViewport.scale 在 WKWebView.pageZoom 和布局调整期间可能不同。主文档工具现在使用自身实时 CSS 视口比例；只在比例/内容缩放发生变化时报告原生，再同步到嵌入播放器。报告检查所属文档 URL 和当前页面缩放，旧文档不能覆盖新文档状态。高度变化和普通滚动继续在本地布局，重复原生输入也会去重。

没有改动 WebKit 原生前进/返回、普通链接请求、缓存恢复、视频源或播放器尺寸。原生媒体桥接 15 项复测通过，包含上述两个原先失败用例。补充 JavaScript 检查验证 50 次相同比例的 resize 不重复报告，并拒绝用过时原生估计替换主文档的实际比例。

## 返回滚动位置测试的前置时序

扩大浏览检查再次复现旧的 `testBackRestoresTheSameDocumentWithoutReloading`：文档身份、缓存和输入内容都保留，但滚动位置为 0，预期 600。

诊断显示，在离开页面前，JavaScript 已读到滚动 600，原生 UIScrollView.contentOffset.y 仍为 0。测试直接合成链接激活，没有等待原生滚动位置提交。现增加更强的前置断言：原生滚动也必须到达 600，才离开页面。没有降低返回后的文档身份、pageshow.persisted、未保存输入、滚动 600 和仅一次原页面请求的断言。

普通页和视频页各重复三轮，六轮的日志均记录原生初值 0、提交后 600，之后全部通过。每轮同时验证 App 返回按钮和直接 WKWebView.goBack，共 12 次返回。此处修正测试同步，不是给产品增加滚动、刷新、截图覆盖或跳过历史逻辑，也不构成所有网站都不会出现恢复问题的保证。

## 真实百度页面检查的边界

实际打开 `https://m.baidu.com/s?word=盐焗`，返回 200、11 个结果。移动 UA Chrome 的隔离世界加载当前媒体状态、视频工具和百度规则。120 帧滚动探针中，去掉首帧后的 119 个间隔中位数约 16.7 ms、P95 约 17.2 ms；该区间媒体新增扫描为 0、缩放桥接报告为 0。滚动后实际媒体和跟踪媒体均为 1。开始时没有 video 元素，因此该页面结果不能代替含大量正在播放视频的真机性能检查。

另打开用户提供的百度视频详情页，实际点击前三个合集视频。各次视频解码帧计数为 167、101、105，时间推进，进入文档全屏，视频内联样式未被改写。此处为真实 Chrome 页面检查，原生 AVKit 全屏由独立 iPhone 模拟器 UI 用例覆盖，不冒充用户 iPhone 上这些影片的实测。

这些数据用于检查脚本增量和功能，不是完整 App 的真机加载/功耗/帧率基准，也不能证明整体性能超过 Safari。特定无音轨 HEVC 样本仍有播放兼容限制；磁力/eD2K 仍依赖在线来源，后台执行受 iOS 调度限制。
