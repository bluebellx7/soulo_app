# 播放器返回停在空白页的补充修复

## 原因与复现

此前的用例只包含完成加载的固定播放器框架。补充真实生命周期后复现：子框架的历史页面在 `pageshow` 时再创建一个用于初始化的空白框架，原导航策略将这个子框架的自动加载也当作取消浏览器返回的理由，连续返回被中断，停在播放器初始化页。修复前 `testBackContinuesWhenRestoredPlayerStartsANestedFrame` 超时，顶层网址仍为 `/player`。

基线结果：`/tmp/soulo-back-oct23-baseline.xcresult`。其中嵌套框架恢复用例失败，加载完成时序用例通过；不将后者作为失败复现证据。

## 修改

- 普通导航只有目标为主框架时才取消连续返回；内层播放器自动加载继续交给原有导航保护和历史处理。
- 主文档的加载完成回调不再无条件取消正在进行的框架历史返回。原有主框架历史导航、主文档状态变化以及用户操作仍结束这次自动遍历。
- 保留 WebKit 原始历史和前进功能，保持逐步等待框架恢复、历史深度递减及回调取消校验。
- 常规回归还发现未挂载 WebView 时，返回和前进动作提前退出，未取消待定跨域确认。调整退出顺序后，11 项跨域导航用例通过。
- 选集、下载大小、分组网格、键盘及此前错误状态修复均保留。没有新增网页注入或轮询。

## 验证

- 不同原生用例共 181 项通过：常规套件中的 180 项及显式启用的实站检查。原全套初次运行有一个跨域控制用例失败（4 条断言），修复后在后续结果包中完整通过该套件。
- 3 项界面检查通过：真实点击两次进入播放器，在恢复框架继续初始化的情况下仅点击一次底部返回，到达列表，并能正常前进；网络失败后的同文档返回；播放器选集在返回、前进后仍可打开。
- 覆盖同网址主文档状态、主状态位于子框架历史之前、子框架同文档历史、迟到错误、POST/重定向及换代理接手加载。
- 真机原标签为片吧《东大高武学院》第 9 集。使用同一真实网址在独立模拟器连续做 3 轮进入/前进到播放页、一次返回详情页；每轮顶层网址及错误状态均符合预期，实站用例 21.949 秒通过。见 [历史记录](2026-10-23-video-back/live-history-three-rounds.txt)。
- iOS Release、签名 Debug 构建通过。旧临时 DerivedData 的模块缓存失效，改用新目录后构建通过，没有改动产品源码来绕过构建错误。
- 真机原安装商店版 1.2.3（37）。本次以命令行 `CURRENT_PROJECT_VERSION=38` 打包调试修复版，覆盖安装并正常启动，保留原数据；安装后读取到原有标签。设备查询确认已安装 1.2.3（38）。
- 工程及商店元数据版本没有修改：源工程仍为 1.2.3（34），38 仅为本机调试构建覆盖值。本轮没有执行真机 UI 自动化，界面和多轮实站检查运行于独立模拟器。
