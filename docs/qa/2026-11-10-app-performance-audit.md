# Soulo 1.2.11 页面与网页加载性能检查

日期：2026-11-10。基于 `973e97e` 和工作区现有修改，版本 `1.2.11 (51)`。

本轮增加可复用的性能审计测试和结果文件。最明确的两项问题是：资料库在大量历史记录、书签下有约一秒的同步布局开销；广告过滤开启时，Apple 首页的 DOM 就绪时间明显增加。测试通过表示测量流程正常完成，不表示所有耗时已经达标。

## 测量范围与口径

- 盘点 `Views` 下 101 个 Swift 文件，测量 **81 个页面入口、373 个布局样本**。设置及子页、平台/分组管理、资料库四分区、下载/文件/阅读、标签管理、浏览器及网页工具均有入口样本。逐页结果见 [CSV](2026-11-10-app-performance-pages.csv)，结构化结果见 [JSON](2026-11-10-app-performance-audit.json)。组件文件盘点不等于每个私有状态都做过运行测量。
- 页面测试使用 **Release、iPhone 17 / iOS 26.2 模拟器、402 pt 宽度**，宿主为 M1 Max / 32 GiB。首轮每页 3 次，异常页及新增入口复测 5 次；历史和书签分别准备 100、1000、5000 条内存数据库记录。两类记录在每档同时存在。
- `layoutMS` 包含创建视图、创建新的 `NavigationStack` / `UIHostingController`、安装窗口和同步布局。它是统一入口的布局代理值，**不是点击到显示的完整耗时，也不是 GPU 帧时间**。表中“首次”是该入口本轮第一个样本，并非每页都独立冷启动；“重复”是其余样本的中位数。
- 首轮 `maxRunloopGapMS` 实际记录 `CADisplayLink` 回调间隔，可能受系统调度影响。复测增加独立后台定时器向主队列投递探针，记录 `maxMainQueueDelayMS`，不再用帧回调间隔直接判断主线程卡顿。
- 网页使用真实 WKWebView 和实际 `AdBlockPreparedWebView`，共 **46 次导航**：四个公网网站两模式各 2 次、本地固定 HTML 三模式各 5 次、Apple 三模式各 5 次。模式轮换顺序，Soulo 使用隐私会话。未全局清空系统/WebKit/规则缓存；本轮结果对应这份 QA 环境中的规则和设置。
- `native_total_ms` 包含 WebView 准备和导航完成等待，完成状态每 100 ms 检查一次；DOM 就绪、TTFB 等来自网页 Navigation Timing。二者时钟起点不同，不能相减充当某个函数的耗时。缺失的 FCP 不当作 0，也不参与比较。

## 1. 资料库与长列表：已复现的同步开销

以下优先采用 5 次复测；100/1000 条采用首轮 3 次结果。

| 页面 / 记录规模 | 首次布局 ms | 重复布局中位数 ms | 复测主队列最大延迟 ms |
| --- | ---: | ---: | ---: |
| 独立历史 / 100 | 158.6 | 109.1 | 未测 |
| 独立历史 / 1000 | 223.0 | 200.8 | 未测 |
| 独立历史 / 5000 | 591.5 | 580.4 | 607.1 |
| 独立书签 / 100 | 198.1 | 120.3 | 未测 |
| 独立书签 / 1000 | 142.7 | 136.1 | 未测 |
| 独立书签 / 5000 | 345.6 | 311.1 | 346.1 |
| 资料库·历史 / 100 | 245.5 | 211.1 | 未测 |
| 资料库·历史 / 1000 | 350.9 | 375.7 | 未测 |
| 资料库·历史 / 5000 | 1041.0 | 1028.7 | 1043.9 |
| 资料库·书签 / 100 | 229.4 | 224.7 | 未测 |
| 资料库·书签 / 1000 | 324.0 | 334.8 | 未测 |
| 资料库·书签 / 5000 | 938.8 | 955.0 | 972.5 |

代码对应位置：

- `Views/Shared/LibraryView.swift` 的 `LibraryPager` 使用普通 `HStack` 创建全部四页；`libraryPageIsActive` 限制导航项和部分任务，但不阻止未显示分区建立查询和布局。
- `Views/Search/SearchHistoryView.swift` 使用无上限 `@Query`，`visibleHistory`、`deduped`、`grouped` 在视图求值中反复遍历数据；日期分组还逐条调用 `Calendar.startOfDay`。
- `Views/Bookmarks/BookmarksView.swift` 全量读取书签和文件夹，再在视图中筛选、计算数量。资料库同时承担历史和书签的成本，与独立页对照一致。
- 已有模型回归中，5000 条历史下单次网页访问记录写入中位数 **1.762 ms**。它与页面的全量读取、投影、布局是不同路径，不能把约一秒都归因于数据库写入。

建议先让未访问分区延后创建，同时保留已访问分区的滚动和选择状态；再将查询限制、分批显示以及筛选/去重/分组结果缓存结合处理。验收必须继续覆盖资料库横向分页、行滑动删除、历史去重、搜索和书签文件夹，不能仅替换成懒加载容器后就判断完成。

## 2. 网页请求：网络首字节与页面处理分开看

首轮公网对照每格只有 2 次，适合定位异常，不适合做站点速度排名。

| 网站 | 原始 WK 总耗时中位数 ms | Soulo 开启过滤总耗时中位数 ms | 原始 WK DOM 就绪 ms | Soulo DOM 就绪 ms |
| --- | ---: | ---: | ---: | ---: |
| 百度首页 | 1565.6 | 2566.7 | 606.5 | 1034.5 |
| StockClaw | 2380.9 | 1959.8 | 371.5 | 1310.0 |
| DeepSeek usage | 1091.8 | 1191.5 | 138.5 | 254.5 |
| Apple 中国首页 | 1250.9 | 3006.2 | 594.5 | 2265.0 |

DeepSeek 测的是匿名/登录外壳，没有登录账户，也没有测 usage API。各模式网站内容和连接复用状态可能不同；StockClaw 两次波动尤其明显，不能按上述差值声称过滤一定加速或减速。

### 同一份本地页面，三模式各 5 次

通过本机标准库 HTTP 服务返回 `Cache-Control: no-store` 的固定 HTML：1200 个结果区块、188861 字节；三模式所有样本正文长度均为 88997 字符，没有登录、外部资源或服务端渲染差异。

| 模式 | 总耗时中位数 ms | DOM 就绪中位数 ms | load 中位数 ms |
| --- | ---: | ---: | ---: |
| 原始 WK | 423.8 | 7 | 13 |
| Soulo 关闭过滤 | 433.7 | 62 | 69 |
| Soulo 开启过滤 | 516.5 | 107 | 113 |

这份页面中，开启过滤相对关闭过滤增加约 **45 ms DOM 就绪时间、83 ms 总耗时**。Soulo 的非过滤脚本也有可测成本，不能把原始 WK 与 Soulo 的全部差距算在过滤上。

### Apple 复测，三模式各 5 次

| 模式 | TTFB 中位数 ms | DOM 就绪中位数 ms | load 中位数 ms | 总耗时中位数 ms |
| --- | ---: | ---: | ---: | ---: |
| 原始 WK | 11 | 369 | 458 | 937.1 |
| Soulo 关闭过滤 | 10 | 287 | 382 | 837.7 |
| Soulo 开启过滤 | 13 | 2203 | 2343 | 2902.5 |

过滤开启时的额外开销复现，而首字节时间接近，优先排查过滤路径中的页面处理工作。公网动态内容仍有差异，且尚未取得 WebContent 进程的函数级 CPU 轨迹，因此**不能将约 1.9 秒精确归因于某一个函数**。

源码中 `AdBlockService` 的文档起始脚本和后续清理会执行 `refreshMosaics`、选择器匹配、遮罩/浮层清理；MutationObserver 也可能再次触发这些工作。这些是下一步剖析对象。优化应关注节点增量处理、扫描范围和每批预算，并用 Apple、百度、验证页和视频站回归；直接关闭保护或按固定延迟跳过过滤不属于本轮结论。

额外做了 4 站 × 3 次 curl GET 参考，原始数据保存在临时产物中。shell 存在代理路径，其 TLS/TTFB 不能直接与 WebKit 对比；DeepSeek curl 返回 202 空正文，也不能当成正常页面加载成功。

## 3. 页面首次进入与搜索转场

首轮 66 个入口的重复布局中位数分布：页面间中位数 **53.9 ms**，范围 **14.6–125.8 ms**。这是统一 Hosting/NavigationStack 的成本分布，不是 60/120 Hz 流畅度结论。

| 入口 | 首次布局 ms | 重复布局中位数 ms | 额外观察 |
| --- | ---: | ---: | --- |
| 设置 | 406.4 | 104.1 | 复测主队列最大延迟 410.7 ms |
| 首页工具栏设置，独立进程复测 | 260.5 | 95.2 | 首次窗口捕获 743.4 ms 主队列延迟，其后 79.7–101.4 ms |
| 全屏快捷菜单 | 238.3 | 121.5 | 主队列最大延迟 241.6 ms |
| 浏览器容器 | 247.9 | 50.8 | 已载入本地文章的容器挂载，不含公网导航 |
| Soulo 视频页 | 193.7 | 66.0 | 本地 H.264/AAC，小型夹具；不是解码首帧或长视频基准 |
| 系统视频页 | 37.4 | 28.5 | 同一夹具；异步准备阶段不同，不能据此比较两播放器播放速度 |

首页工具栏首次的主队列延迟比同步布局本身更长，说明还需要剖析后续 SwiftUI 更新和共享服务任务。首轮约 2 秒的 display 回调间隔没有在独立复测中以相同数值复现，**不保留“工具栏必卡两秒”的说法**。地址编辑页观察窗口曾记录 370 ms 主队列延迟，需结合键盘和共享任务单独定位。

另运行现有启动脚本 12 次，均为 **Debug 模拟器、应用进程重启**，没有清空 OS/WebKit 缓存。搜索前等待 2.5 秒时：

- 开启 WebKit 预热：提交到可见内容中位数 **564.1 ms**；不预热为 **1019.9 ms**。
- 预热后 WebView 获取约 **0.2 ms**，脚本安装约 **15.7 ms**，但提交到 WebView 挂载仍约 **411.4 ms**。此段发生在网络导航之前，有继续优化搜索状态更新和页面转场的空间。
- `performSearch` 同时更新搜索状态、平台使用情况和 Live Activity；这些只是剖析入口，现有数据不足以分别给它们分配耗时。

## 4. 真机结果与尚未测到的范围

用户解锁后的 iPhone 17 / iOS 26.6.1，已安装 Soulo 1.2.11 (51)，完成一条有效的 Instruments App Launch 轨迹，记录长度 15.76 秒、正常达到采样时限：

- 初始帧渲染阶段 **228.86 ms**。
- 从轨迹起点到 Foreground Active 约 **1.064 秒**，其中系统进程创建约 **721.23 ms**。
- 单次受 Instruments 影响的样本；已安装构建配置未确认。生命周期存在重叠区间，不能相加或当成正式 Release 启动统计。

真机网页/滚动自动化在 XCTest 驱动与 IDE 建连前中断，错误包含 `XCTestManager_IDEInterface` 通道拒绝及退出码 74。尝试硬件 UDID、去除注入环境及直接项目运行后仍是驱动建连失败，**没有任何实际网页/滚动测试执行，因此不报告真机网页速度**。没有覆盖安装用户真机上的应用。

本轮也未运行 iPad 页面基准，未把改变窗口宽度当成 iPad 数据。系统相机、麦克风、照片选择、系统分享/文件选择器、已安装扩展的更新/权限状态、活跃种子任务、大型导入书籍/视频和真实云同步，需要对应真实输入或隔离夹具另测。81 个入口覆盖主要应用页面，不代表这些所有状态都已完成性能验收。

源码扫描中的多处文件读取已在 `Task.detached` 中，包括书籍解析、文件夹枚举、文本解码和许可证读取，不应再笼统归因为“全部在主线程读文件”。备份导入回调中的同步读取和解析属于操作阶段的后续剖析项，本轮没有测其大文件耗时。

## 验证、复跑与产物

- `page-audit-release-v2.xcresult`：2 项审计 + 13 项既有性能回归通过，0 失败。下载 1000 次进度更新约 2.809 ms / 1 次落盘 / 1003 次发布；隐私计数 500 次更新约 16.147 ms / 1 次落盘。发布次数不等于实际 UI 重绘次数，没有据此宣称下载时滚动流畅。
- `targeted-release.xcresult`：2 项审计通过，125 个布局样本和 15 次本地网页导航。
- `apple-and-toolbar-release.xcresult`：2 项审计通过，5 个独立工具栏样本和 15 次 Apple 导航。
- `python3 scripts/check_localization.py --strict` 通过；`python3 scripts/export_metadata_json.py --check` 验证 50 个语言目录通过。
- 所有原始 JSON、日志、xcresult、启动样本及真机轨迹位于 `/tmp/soulo-app-perf-20261110/`，另有 `/tmp/soulo-app-perf-*-20261110.log`。没有调用付费服务。

审计入口为 `SouloTests/AppPerformanceAuditTests.swift`，默认跳过。复跑示例：

```sh
TEST_RUNNER_SOULO_APP_PERF_AUDIT=1 \
xcodebuild test -project Soulo.xcodeproj -scheme Soulo \
  -configuration Release \
  -destination 'platform=iOS Simulator,id=BECE20B7-B626-440B-A31E-797AB97487DF' \
  -parallel-testing-enabled NO \
  -only-testing:SouloTests/AppPerformanceAuditTests \
  ENABLE_TESTABILITY=YES ONLY_ACTIVE_ARCH=YES ARCHS=arm64
```

可选环境变量均加 `TEST_RUNNER_` 前缀传给 xcodebuild：`SOULO_APP_PERF_PAGES` 为逗号分隔的页面名；`SOULO_APP_PERF_ROWS` 默认 `100,1000,5000`，`none` 禁用数据规模轮次；`SOULO_APP_PERF_REPEATS` 为 1–10；`SOULO_APP_PERF_URL` 指向单个受控页面；`SOULO_APP_PERF_MODES=webkit,soulo_ads_off,soulo_ads_on` 做三模式对照。数据库和文件采用测试夹具，播放器在页面结束和测试退出时停止。

建议按顺序处理：**资料库全量计算 → 复杂网页过滤处理 → 搜索挂载前耗时 → 设置和菜单首次创建**。每项修改后使用同一夹具与相同构建配置对照，保留中位数和慢样本，最后补真机交互验证。
