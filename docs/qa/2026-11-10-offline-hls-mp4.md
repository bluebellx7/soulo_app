# 离线 HLS 导出 MP4（2026-11-10）

## 使用与范围

- 下载列表中，已完成 HLS 的右侧导出菜单和长按菜单提供“导出 MP4”。成功后新增一条 MP4 记录并打开系统分享面板，原 HLS 保留。
- 资料库文件列表及网格的长按菜单也提供该操作，MP4 保存到当前目录。
- 支持本项目 `.soulohls` 引用和 TS 型 `.movpkg` 中的单视频轨 H.264、可选单 AAC/ADTS 音轨，包含普通 AES-128 加密、显式 IV、按媒体序号生成 IV、编码参数不变的时间线中断。
- HEVC、其他音频编码、多音轨、编码参数中途变化、非 TS 分片及 FairPlay 不在本次支持范围内。单个分片上限为 64 MiB，避免转封装器累计过多内存。无法处理时不发布不完整的 MP4。
- 取消和失败都会清理转换临时文件，原下载及播放进度保留；已有 MP4 和进行中的下载文件名不会被覆盖。

## 最终实现

`OfflineVideoConversionService` 在临时目录建立分片硬链接，复用 `PortableHLSBundle` 的清单和密钥校验。普通 AES-128 由系统 CommonCrypto 按块解密，压缩音视频数据通过 typed array 交给独立 JavaScriptCore 上下文内的 mux.js。脚本只从 App 包加载，不执行网页脚本，不上传视频。已保存密钥的下载无需访问原站；缺少旧版密钥时沿用现有的密钥补存流程。

mux.js 的 MSE 输出需要修正两项文件兼容信息：把初始化头的未知时长 `UINT32_MAX` 改为零，让系统从完整分片计算时长；把各音视频 `moof/mfhd` 的序号改成全局递增。随后使用系统 `AVAssetExportPresetPassthrough` 写成带索引的普通 MP4，核对播放能力、音视频轨和总时长后才发布文件。全程不重新编码。

依赖固定为 mux.js **7.1.0**，压缩脚本 **116,059 字节**，Apache-2.0 许可及来源已加入 App 的 `MediaPlaybackThirdPartyNotices.txt`。

- 上游：https://github.com/videojs/mux.js/tree/v7.1.0
- 分发：https://unpkg.com/mux.js@7.1.0/dist/mux.min.js
- SHA-256：`eb088a07f954554db7c38114487b21df6d1f28c4a84d53003644e962c7567b5b`

没有新增 FFmpeg 或其他二进制媒体框架。新增 Swift/资源文件后已按 `project.yml` 重新生成工程，未修改版本号或商店元数据。

## 未采用的 VLC 路径

现有 MobileVLCKit 3.7.5 的 `sout=standard{access=file,mux=mp4}` 可以生成能播放的文件，但本次 8 秒测试片的源视频为 120 帧，默认 HLS/TS 路径导出只有 118 帧，强制 avformat 解复用也只有 119 帧。解码后逐帧散列对照确认默认路径缺少源视频第 117、118 帧。不能仅凭文件能打开或存在音视频轨认定完整，因此最终采用轻量转封装器。
