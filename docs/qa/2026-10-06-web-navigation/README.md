# 网页导航性能优化（2026-10-06）

用户反馈网页访问仍然偏慢。本次保留广告过滤和隐私保护，通过实际启动 App 分段计时，减少导航时重复传输与解析页面脚本的开销。

## 条件与结果

基线：`d81db5b`，Soulo 1.2.0 / Build 27；优化版本保持相同版本号。iPhone 17 Pro / iOS 26.2 模拟器、Debug、同一台 Mac。每组 3 次，开启和关闭备用 WebView 按轮次交替。采样期间没有并行构建或运行 Soulo 测试。

使用项目已有的 [测量脚本](../../../scripts/benchmark_webview_startup.py)，从 `search_submit` 到 `content_visible` 计时。该信号表示页面内容就绪，不等于完整资源下载或像素级首屏测量。每轮冷启动 App 进程，模拟器系统保持启动。本地页面无外部资源，HTTP `no-store`；本地 HTTP 的 HTTPS 升级仅通过进程启动参数关闭。

以下为中位数：

| 本地页面场景 | 修改前 | 修改后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 启动后快速进入，开启预热 | 2481.5 ms | 1248.1 ms | 49.7% |
| 等待预热，开启预热 | 1888.9 ms | 757.7 ms | 59.9% |
| 等待预热，关闭预热 | 2469.9 ms | 1184.2 ms | 52.1% |

“快速进入”指 `pool_activate` 后等待 0.1 秒；“等待预热”指等待 2.5 秒，还包含系统 URL 路由和界面切换耗时。快速进入时备用 WebView 不一定就绪，因此应将其理解为实际快速进入场景，不是固定的备用池命中比较。等待 2.5 秒且开启预热的分组，修改前后均为 3 次已就绪命中。

基线首次升级后的两个快速进入样本还包含缓存准备，耗时较高；保留在原始数据中，未当成稳定缓存命中的样本另行宣传。主要对比使用后续的等待预热分组。优化版本先完成一次准备，再采集三轮数据。首次安装、升级或规则变更后的生成成本仍存在。

优化后的真实 Bing `swift` 搜索完成 6 次内容就绪测量，开启预热的中位数为 2335.7 ms，范围 1908.9–4763.7 ms。网络波动明显；本次未采集同日基线 Bing 数据，不据此计算真实网站的前后提升比例。

原始数据及分段计时见 [measurements.json](measurements.json)。模拟器结果不能直接代表真机或所有网站；本地页面的约 60% 是本次测量结果。

## 变化

- 自动广告脚本在文档开始时安装，按配置签名复用。普通导航、提交和加载完成不再发送完整规则脚本；规则、开关或白名单变化时更新当前和后续文档。
- 手动规则的脚本配置与当前 URL 分开记录。URL 变化时发送短配置更新，只有实际配置变化才重新安装脚本，保留下载、复制、扩展等其他脚本。
- 广告规则采用 `[选择器, 包含域名, 排除域名]` 的紧凑 JSON，使用 `JSON.parse`，减少大量 JavaScript 对象字面量的编译。测量时完整脚本由 7,871,090 字节减少到 5,225,177 字节，约减少 33.6%；仍保留域名限制、排除域名和例外规则。
- 统一安装、更新和手动重载中的兼容站点白名单，避免配置签名不一致导致重复生成。
- 最终检查补充自动脚本的独立标记，避免设置更新时误移除读取广告状态的用户脚本；白名单和验证页跳过订阅 JSON 的解析；已经加载但尚未安装运行时的 WebView 只初始化一次当前文档。
- 验证页通过 History API 切回普通正文时，为同一文档补一次过滤初始化；新的普通文档继续使用文档开始时的脚本，不增加重复的大脚本传输。

这些补充没有改变普通新导航的规则匹配和复用算法。回归首次发现“已加载 WebView 接入界面”的手动选择桥未初始化，已补上当前文档的一次初始化路径。

## 回归验证

- 270 项相关单元用例中 266 项通过、4 项按环境跳过；广告点击与垃圾剪贴板保护的 2 项 UI 用例通过。此次运行共 268 项通过、4 项跳过、0 失败，结果见 [validation.json](validation.json)。
- 3 项工具栏 UI 用例此前已通过，覆盖慢资源页面、站内链接、返回与首页、键盘收起后的操作。
- 补充验证页的 History API 路径后，复查浏览导航、手动过滤和 WebViewModel 的 141 项用例，全部通过，结果见 [validation-spa.json](validation-spa.json)。该轮与前一轮有覆盖重叠，未将两轮相加作为独立用例数。
- 新回归检查普通多域名导航的脚本对象身份与单次广告配置、开关对当前和后续文档的生效、用户脚本保留、带中文与转义引号的选择器、包含和排除域名、例外规则、白名单延迟解析、验证页的站内脚本导航。

4 项跳过的原有用例需要 `SOULO_LIVE_MEDIA_QA`、`SOULO_QA_DIRECT_URL` 或 `SOULO_QA_LOCAL_HLS_PORT` 等专项环境，未计入通过数。

最终 `generic/platform=iOS`、arm64、Release 构建通过，关闭签名进行设备架构编译检查。最终构建未报告源码编译警告。`git diff --check` 与测量 JSON 的完整性检查通过。

本机结果包：`/tmp/soulo-browse-final-20261006.xcresult`、`/tmp/soulo-browse-spa-20261006.xcresult`；最终 Release 日志：`/tmp/soulo-browse-release-final-20261006.log`。临时结果包未纳入仓库。

## 复现

安装正常 Debug 构建到专用测试模拟器，完成首次打开确认和规则准备后运行：

```sh
python3 scripts/benchmark_webview_startup.py --device <UDID> --repeats 3 --delays 0.1 2.5 --output /tmp/soulo-local
python3 scripts/benchmark_webview_startup.py --device <UDID> --repeats 3 --delays 2.5 --url 'https://www.bing.com/search?q=swift' --output /tmp/soulo-bing
```

脚本会终止并重新启动指定模拟器上的 Soulo，应使用独立测试模拟器。计时与预热开关只在 Debug 中生效，未增加面向用户的选项。
