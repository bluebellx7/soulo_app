# 速度、内存、耗能与磁盘检查（2026-10-29）

范围：当前工作区的 Soulo 1.2.6（51），包含本轮插件管理改造。保留已有修改，未提交、推送或发布。插件部分见 [全应用检查的续改记录](2026-10-29-full-app-audit.md#插件管理续改2026-10-29)。

本轮确认需要优化的部分是大图解码、无播放时的视频心跳、自动壁纸任务及低电量/高温时的预热。另修复缓存统计漏算和清理后旧任务回写。历史查询和批量写盘已有有效措施，本轮没有据测量波动改写其实现。没有获得真实设备的电量、焦耳或完整应用内存峰值，不能给出续航提升百分比。

## 已落实的改动

| 范围 | 问题与处理 | 验证 |
| --- | --- | --- |
| 壁纸内存与解码 | 使用 ImageIO 按显示需要解码，保留方向、避免放大小图；网络及预载解码移到 utility 任务。自选照片按需载入，切换纯色/渐变时释放不再使用的位图，原压缩文件保留。 | 6000 × 4000 夹具的显示位图从 96,000,000 降至 24,000,000 字节，减少 75%；旋转、小图、无效数据通过。只代表该位图，不代表 App 总内存减少 75%。 |
| 视频保屏心跳 | 原先每个注入页面/框架常驻 10 秒轮询。现在只在可见页面有播放视频时保留一个定时器，暂停、结束、隐藏和 pagehide 时停止，恢复显示时重新判断。 | 实际生产 JavaScript 在 JavaScriptCore 执行：闲置 0、播放 1、暂停/隐藏 0 个心跳定时器；原有媒体回归继续通过。 |
| 电量与温度 | 统一观察低电量和 thermal state；低电量或 serious/critical 时释放备用 WebView、取消可选预热、暂停自动壁纸刷新和动画。显式导航、手动刷新仍可进行；前台及资源状态恢复后重新判断。 | 注入电源状态通知，验证备用实例释放、当前标签状态保留、显式网页仍可执行、恢复后重新准备。 |
| 壁纸生命周期 | 后台时取消刷新 timer、预载和自动刷新任务；timer 加入容差。以 generation 防止已取消的旧任务覆盖新请求或清空新任务状态。 | 前后台、低电量切换和刷新偏好保持的专项用例通过。 |
| 缓存空间 | 缩略图实际保存在 Application Support，旧统计只看 Caches。现统计实际目录及旧目录；清理先使内存和排队的读取/截图失效，再等待磁盘删除，防止已清理文件重新出现。 | 清理前已排队截图不回写；清理后的新截图仍能保存。标签生命周期 14 项重测通过。 |

电源策略依据 [Apple 的低电量与温度响应说明](https://developer.apple.com/documentation/xcode/responding-to-power-notifications)；timer 容差和减少无用唤醒参见 [Timer.tolerance](https://developer.apple.com/documentation/foundation/timer/tolerance) 与 [Energy Efficiency Guide](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/EnergyGuide-iOS/MinimizeTimerUse.html)。资源策略订阅延后到主队列读取状态，避免在 [`@Published` 的 willSet 通知](https://developer.apple.com/documentation/combine/published) 中误读旧值。

### 启动与首次内容

固定本地 HTTP 页面，无外部脚本、图片和字体，响应 `no-store`。Debug 中显式启用诊断环境变量，从正常搜索入口提交；每次终止并重新启动 App，模拟器系统保持启动。每组 3 次，预热开关交替，共 12 个有效样本；之前的 2 次 priming 不纳入统计。采样使用渐变壁纸、关闭自动壁纸刷新及云同步的进程参数，避免无关网络任务影响。

- 最终 arm64 **Release 设备构建未压缩包体 48,430,104 字节（48.43 MB / 46.19 MiB）**，不含 XCTest 框架。主二进制 36,650,152、Assets.car 4,147,192、trackerData.json 1,575,296 字节，其余为扩展、本地化及资源。不是 App Store 压缩下载或设备裁剪后的大小。
- 性能改动前、插件管理改动后的同口径包体为 48,397,544 字节；本轮增加 32,560 字节。没有把此次内存优化称为包体缩减，也没有删除语言或用户原有素材。
- 专用 Debug 模拟器经过回归及 12 次启动后的数据容器共 8,311,980 字节，Library 占 8,309,460 字节。这只是该夹具使用量，不包含 App Group、安装包和独立 WebKit 进程，也不代表长期用户的下载及缓存量。
- 复核现有 favicon 解码/缓存上限、闲置标签数量限制、内存警告清理，以及下载/统计合并持久化；本轮未发现需要绕开这些机制另建缓存的依据。下载文件和用户安装的扩展属于保留数据，未为减小数字删除。

## 验证与失败记录

- 优化前相关基线 `baseline.xcresult`：37/37 通过。
- 最终相关回归 `regression-final.xcresult`：355 项，347 通过、6 跳过、2 项失败。两项均定位到旧夹具等待条件：WebContent 实际启动 16.003 秒超过缩略图夹具 15 秒期限；另一个 SABR 夹具用固定 1 秒等待，但 WebContent 启动耗时 1.489 秒。分别改为等待实际页面标题和 fixture 数据准备完成，最长 30 秒，保留原功能断言，失败时清理窗口。
