# 首页输入与网页加载过渡

本文记录上午第一轮输入与加载验证；最终半透明样式、返回及分组手势的补充修复见 [后续检查](2026-10-24-browser-refinement.md)。

## 反馈与证据

用户反馈 #35 来自 1.2.3（37）：首页输入延迟，系统拼音偶尔将第一个字母直接提交；本轮同时处理网页访问时整屏黑色加载画面。

- 在实际 HomeView、原生 UITextField 和窗口环境中输入 13 个字母，修改前 SearchViewModel 发出 52 次全局 objectWillChange 通知。修改后同一用例为 0，输入、选区和焦点仍正确。这是全局状态通知次数，不是帧率或输入耗时测量。
- 修改前的手动 marked-text 用例通过，未稳定复现用户所述首字母拆分。因此不将该用例写成已复现的缺陷，也不将状态刷新次数直接等同于首字母问题的唯一原因。37 之后已有的焦点修复继续保留。
- 旧加载提示本身只是顶部小胶囊；黑色主要来自尚未绘制内容的深色 WKWebView 底板。

## 修改

- 将草稿、组合状态和联想结果移至 SearchInputState，搜索控件和联想浮层分别观察，逐键输入不再发布整个浏览器导航状态。
- 首页、顶部搜索和新标签搜索由原生 UITextField 保持组合文本和光标。普通 SwiftUI 更新不回写键盘刚输入的文本，只有清空、填入建议、语音等明确操作才替换文本。组合期间不提交搜索，不发送联想请求；取消及过期请求不能恢复旧建议。
- 输入首字母后隐藏最近搜索但保留布局，避免搜索框跟随重排。输入聚焦时延后壁纸加载、规则预热及备用 WebView 创建，不延迟用户主动打开网页。
- 底部地址编辑器在组合期间也避免非主动文本回写，并保护 Return 提交。
- 新 WebView 首次加载以静态首页背景和域名提示承接。已有内容跳转时保留原生内存画面，顶部细进度条反馈加载；新内容可见、完成、停止、失败及卸载时清理画面。已有标签恢复截图仍优先使用。
- 复用原有首屏可见消息，没有新增网页注入脚本或页面轮询。每次导航使用临时原生视图快照，不新增磁盘截图写入。

## 验证

- 核心测试 226 项：225 项通过，1 项实站播放器用例按既有环境条件跳过，0 失败。覆盖搜索、组合输入、预热、性能回归、标签恢复、窗口布局、历史导航及网页生命周期。
- 5 项不同界面用例最终均通过：系统拼音候选选择/清空重输/整词搜索；真实百度搜索框和键盘；地址键盘收起后的工具栏；首次背景及后续导航画面与返回；慢资源未完成时的菜单、标签切换、页面链接和返回首页。
- 系统拼音通过实际点击屏幕键盘输入 nihao、选择“你好”，清空后输入 zhongwen、选择“中文”，提交并检查地址编辑器中的整词。没有使用直接粘贴中文来替代输入法验证。截图确认拼音下划线及原生候选词，组合期间没有网页联想覆盖。
- 初次界面运行有失败，未计作通过：加载组件被测试误查为 Other，实际为组合后的 StaticText；慢网页用例选中持久化的同名旧卡片。前者改为按组件标识查询，后者限定 overview 卡片并使用唯一页面标题，保留完整交互断言后重跑通过。
- Release 和签名 Debug 构建通过。严格本地化检查通过（877 键 × 50 语言）；元数据生成文件 --check 通过；git diff --check 通过。
- 工程及商店版本保持 1.2.4（34）。仅命令行覆盖调试构建号为 41，覆盖安装到连接 iPhone，设备查询为 1.2.4（41）。镜像中成功启动到首页，原有 20 个标签仍在；没有卸载或清除数据。之后手机被使用导致镜像断开，未完成真机系统拼音复测，也未取得真机输入延迟/帧率数据。
