# 网页视频全屏与 VLC 归档符号（2026-11-01）

## 网页视频全屏

用户报告百度视频详情页中第一个以外的视频无法进入全屏，或者进入后黑屏。样例为 `https://m.baidu.com/video/page?pd=video_page&nid=15094759295704557078&sign=4269360879922130099`，完整用户网址保留在临时检查目录。

代码中发现两处风险：后续未加载/正在切换源的视频会立即调用全屏 API；进入前会强行覆盖视频的 width/height 等内联样式，可能干扰网站自身的响应式播放器。

本轮调整只涉及明确点击视频工具的全屏流程：

- 保留原有视频元素、视频源及站点尺寸，不提取 URL，不重新创建播放器，不调用 load()。
- 已在播放且具备当前帧的视频继续同步进入原生全屏。
- 暂停或尚未加载的后续视频在真实点击中启动播放，等待播放就绪、当前帧及有效尺寸后进入全屏。
- 原生 API 不可用或拒绝时，尝试受支持的文档全屏 API；失败保留原有错误提示。
- 进入成功、失败、导航离开、视频移除时清理本次等待事件。旧播放 Promise 完成不能在新页面重新打开全屏。
- 保留原有 AVKit 事件和文档全屏事件的区分，避免无关 fullscreenchange 立即结束横屏。

没有增加页面后台轮询、常驻观察器或滚动工作。

验证：

- 更新后的 JavaScript 回归在修改前因视频尺寸被覆盖失败，修改后通过。覆盖延迟媒体、原生拒绝后的回退、独立退出事件、导航取消及尺寸保留。
- 视频工具性能回归通过：纯文本动画零额外工作、子树合并扫描、100 个视频下只读取附近几何、隐藏祖先、后续视频和 Shadow DOM。
- `NativeFullscreen.xcresult` 两个 iPhone 模拟器 UI 用例通过，覆盖正常内联视频和后续 preload=none 视频、复用播放器切换源、原生关闭与方向恢复。
- `NativeFullFrame.xcresult` 加强了画面验证并定向重跑后续视频用例：通过。使用 XCUIScreen 整屏截图及中央区域非黑像素检查，确认完整视频画面；人工复核截图通过。App 局部截图在本机模拟器横屏时存在裁切差异，未据此改写产品尺寸或降低整屏验证。
- 用户真实百度页面的前三个合集视频在移动 UA 的 Chrome 实际点击检查中均进入文档全屏，视频时间推进、解码帧计数为 172/111/107，视频内联样式保持未覆盖。此处是 Chrome 的真实站点检查，不冒充 iPhone 上该站点的 AVKit 全屏实测。
- 此次未在用户 iPhone/iPad 上进行自动化操作。真实设备仍需用户确认该页面；不据此保证任意站点视频都支持全屏。
