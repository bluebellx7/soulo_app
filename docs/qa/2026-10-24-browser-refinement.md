# 加载、设置、返回与分组手势检查

## 最终行为

- 加载时保留清晰背景，仅居中的紧凑盒子使用半透明玻璃；盒内双短弧以 0.9 秒一周旋转，域名和加载文字居中，使用固定深色局部表面及白色指示保证对比度。没有光晕、呼吸或全屏磨砂，盒子的位置避开底部工具栏；后台或“减少动态效果”下停止旋转。首次内容出现前保留 WebKit 渲染、将其空白底板透明；内容可见后恢复正常网页底板与 WebKit 自动的页面衬底颜色。后续导航仍暂留上一页原生画面，不增加网页脚本或逐帧计时器。
- 首屏内容就绪后，用 0.18 秒淡入网页并淡出加载盒子；后续导航的旧页面预览、标签恢复的截图也采用相同长度的淡出。没有增加最短等待时间。首次淡入使用临时原生图层遮罩，完成即移除，不给后续浏览或视频留下持续合成遮罩；“减少动态效果”下直接显示。原生加载完成和重新挂载已完成文档都有兜底，避免 PDF 等没有 HTML 首屏回调的内容一直被遮住。
- 设置主页使用值导航，点击后才创建子页，避免首次弹出时同时构造广告规则、扩展等目的页并读取其存档。缓存大小仅在对应行出现后异步统计，取消后不再写回界面。不将界面自动化耗时当成实际卡顿改善量，未采集真机帧率对比。
- 通用返回处理记录没有用户交互、由页面自动发起的主文档跳转。底部返回、原生 WebKit 历史返回和前进跳过这些中转记录；保留真实历史项及正常链接、同网址状态和子框架历史逻辑。没有百度或其它域名判断，也不凭 URL 关键词、固定延时或页面文案跳过历史。
- 分组卡片可左滑关闭，拖动时显示删除图标，未达到阈值松手复位。手势先锁定横/纵方向，纵向拖动交给列表滚动。关闭依据标签 ID 重新定位，保留网格重排、最近使用顺序、固定底栏和无障碍关闭操作。
- “在默认浏览器中打开”先交给系统。若同一网址立即返回 Soulo，消费这一次交接而不再创建标签，然后打开 Safari。只匹配该次操作的精确网址并设置短期有效期；其它进入 App 的链接照常处理。外部 App 自定义协议仍使用原有打开流程。

## 返回问题的基线与修复验证

- 真实百度“鸡蛋”搜索结果中，搜索页与百科正文之间存在一条独立的自动中转历史。修改前一次返回再次到达百科，未回到搜索页。结果包：`/tmp/soulo-baidu-back-live-baseline2.xcresult`。此次真实基线没有显示 App 错误覆盖层，不把它写成“加载失败”画面已被实站稳定复现。
- 本地通用 HTTP 用例让中转页第一次正常跳转、再次请求立即断开连接。修改前，底部返回和 WebKit 原生返回两个用例均停在中转 URL，无法到达之前的表单页：`/tmp/soulo-redirect-history-baseline.xcresult`。
- 修复后两个通用用例通过，返回不再重请求中转地址，前进仍到达正文。另有普通链接事件缺少手势桥消息时的保护用例，防止误跳过正常访问页面。
- 单独启用的真实百度用例通过，一次返回到原搜索 URL，错误状态为空：`/tmp/soulo-baidu-back-live-fixed.xcresult`。
- 屏幕点击用例也通过：真实点击“鸡蛋－百度百科”结果，等到目标域名后点击一次底部返回，搜索结果恢复且无失败提示。结果包：`/tmp/soulo-baidu-and-external-ui.xcresult`。

## Safari 交接的边界

系统默认浏览器查询接口有频率限制，因此路由不依赖反复查询或长期缓存该状态，使用本次明确外部打开后的实际 URL 递送结果。[Apple 默认浏览器说明](https://developer.apple.com/documentation/xcode/preparing-your-app-to-be-the-default-browser)

HTTPS 回流使用 Safari 注册的 `x-safari-https` 协议，保留路径、编码查询和片段。已查看本机 iOS 26.2 Simulator 的 MobileSafari.app/Info.plist，其非私有 URL 类型注册了此协议；没有使用带 `CFBundleURLIsPrivate` 的 Safari Tab 协议。HTTP 没有改成 HTTPS，使用系统 SFSafariViewController 兼容页；Safari 不可用时也回退到系统兼容页。这一回退位于 App 内，不冒充已经打开外部 Safari App。
